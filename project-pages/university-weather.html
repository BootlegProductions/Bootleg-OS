Weather Application

An earlier weather-dashboard project that explored API requests, dynamic data, SVG animation and progressive-web-app ideas.

Original specification

The application was designed around searched locations, condition imagery, temperature, humidity and wind speed using OpenWeatherMap data. The specification also explored error states, smooth UI transitions and progressive-web-app installation.

Why it matters now

Several ideas from this university project have returned in the current Bootleg OS Weather Station: API-driven forecasts, location search, weather data visualisation and an animated clock concept.

From search to forecast

This Advanced Front-end Web project began with a straightforward interaction: enter a place, request current conditions and update the page without a full reload. The specification called for a prominent temperature, a matching condition image, humidity and wind speed. It also planned a clear 404 state when a search could not be matched, while keeping the page layout familiar.

The archived work contains an initial weather-app exercise and a more developed site with separate HTML, CSS and JavaScript files, weather icons, a manifest and a service worker. That progression matters: I was moving from a single functional search screen towards a more complete application with installable-app ideas and a distinct visual identity.

Designing beyond the happy path

I explored transitions between conditions and error states, small visual cues in the search field, and an animated SVG clock driven by the visitor's local time. The written specification also considered progressive-web-app installation and offline support. Those were design and implementation goals; an online forecast still depends on network access to return fresh weather data.

Several ideas later found their way into the current Bootleg OS Weather Station, particularly location search, API-driven data and weather-specific visuals. The original project remains useful as a record of how I learned to connect an interface to live data and then design for what happens when that data is missing.
