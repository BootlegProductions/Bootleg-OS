PIP-BOY V0.4 — BASIC SETUP & RECOVERY MANUAL

Working reference for Oliver’s Raspberry Pi Pip-Boy Last updated: 29
September 2026

IMPORTANT

This records the setup that is currently known to work.

Normal end state: Power on -> Raspberry Pi desktop -> touchscreen works
-> tap Pip-Boy desktop launcher -> Pip-Boy V0.4 launches.

The Pi has previously reported UNDERVOLTAGE because it has been powered
from an improvised power-bank setup. Avoid large system upgrades or
unnecessary power cycling until a better permanent power supply is
installed.

3. LAUNCH THE PIP-BOY MANUALLY

Connect through SSH, then:

    cd ~/pipboy
    DISPLAY=:0 SDL_VIDEODRIVER=x11 python3 pipboy_v04.py

This explicitly launches Pygame onto the Pi’s X11 desktop/display.

Do NOT change this to the Wayland driver on the current setup. A
previous Wayland launch failed with:

    pygame.error: wayland not available

To stop a manually launched program from the terminal:

    Ctrl+C

8. DISPLAY SETUP

The touchscreen/display currently uses the modern MHS35 / piscreen
setup.

Important working display line in:

    /boot/firmware/config.txt

is:

    dtoverlay=piscreen,speed=18000000,drm,rotate=180

The old vc4-kms-v3d line was disabled during repair.

The display is currently rotated correctly.

SCREEN ROTATION

The working orientation is controlled by:

    rotate=180

in the dtoverlay line above.

Do NOT casually change rotation, display overlays, touchscreen matrices,
or reinstall LCD drivers just to experiment. Display orientation and
touchscreen orientation are related but are not the same setting.

If rotation ever genuinely needs changing, BACK UP
/boot/firmware/config.txt first and change only the rotation value
deliberately.

9. TOUCHSCREEN — KNOWN-GOOD CALIBRATION

11. DISPLAY DRIVER INSTALLATION / RECOVERY

The old fbcp-based display setup became incompatible after the OS/kernel
update.

The working modern MHS35 installer used during recovery was:

    cd /tmp
    rm -rf LCD-show
    git clone https://github.com/ahamedfaisal-dot/LCD-show.git
    cd LCD-show
    chmod +x MHS35-fixed-install.sh
    sudo ./MHS35-fixed-install.sh

IMPORTANT: This section is for RECOVERY, not routine startup.

Do NOT rerun the LCD installer when the display is already working.

The old fbcp startup was removed from /etc/rc.local. It was left
effectively as:

    # Old fbcp disabled - Xorg now uses /dev/fb1 directly
    exit 0

12. LIGHTDM 90-SECOND BOOT DELAY FIX

After the graphical update, LightDM was waiting for a nonexistent:

    /dev/dri/renderD128

The working repair was:

    sudo cp /lib/systemd/system/lightdm.service /etc/systemd/system/lightdm.service
    sudo sed -i 's/ dev-dri-renderD128\.device//g' /etc/systemd/system/lightdm.service
    sudo systemctl daemon-reload

The local file:

    /etc/systemd/system/lightdm.service

now intentionally overrides the packaged LightDM service.

IMPORTANT: A future package update may change the packaged LightDM
service, but the local override remains intentional. Do not delete it
simply because it differs from /lib/systemd/system/lightdm.service.

13. PLYMOUTH / SPLASH

The graphical Plymouth splash was intentionally disabled.

The system uses:

    disable_splash=1

and the kernel command line includes:

    quiet plymouth.enable=0

plymouth-quit-wait.service was also masked.

The desired behaviour is a quick boot with some brief console text
followed by the desktop. A graphical Raspberry Pi splash is NOT
required.

14. PYGAME AUDIO — IMPORTANT FIX

Radio playback originally crackled/chopped inside the full Pip-Boy
application even though direct audio playback was clean.

The important fix was to initialise the Pygame mixer BEFORE
pygame.init().

In pipboy_v04.py, immediately before:

    pygame.init()

use:

    pygame.mixer.pre_init(
        frequency=44100,
        size=-16,
        channels=2,
        buffer=4096
    )

    pygame.init()

This fixed the audio problem.

Do not remove this pre_init block unless intentionally testing audio
configuration.

15. AUDIO OUTPUT / AUX

List ALSA playback hardware:

    aplay -l

The Pi previously showed a separate bcm2835 Headphones device.

Direct AUX/speaker test example:

    speaker-test -D plughw:1,0 -c 2 -t sine

Stop speaker-test with:

    Ctrl+C

PipeWire device/routing status:

    wpctl status

The headphone sink ID has previously been 71, BUT NUMERICAL IDs CAN
CHANGE AFTER REBOOT.

Always run:

    wpctl status

before using a numeric sink ID.

Set the current headphone sink as default:

    wpctl set-default <SINK-ID>

Example only:

    wpctl set-default 71

Set normal clean volume:

    wpctl set-volume <SINK-ID> 1.0

100% PipeWire volume plus 100% Pygame music volume gave cleaner audio
than heavily boosting the software sink.

For additional loudness, use the physical amplifier/speaker volume
rather than excessive digital boost.

16. TEST AN AUDIO FILE OUTSIDE PYGAME

Use PipeWire’s player:

    pw-play /path/to/song.mp3

If pw-play is clean but the Pip-Boy application crackles, that points
toward application/mixer configuration rather than the physical AUX
output.

The Pygame mixer can be checked from Python with:

    import pygame
    pygame.init()
    print(pygame.mixer.get_init())

The working mixer format was:

    (44100, -16, 2)

and buffer 4096 proved clean during testing.

18. PYGAME / TOUCH PERFORMANCE

The modern SPI ILI9486/piscreen display is slow at full-screen updates.

A full-screen Pygame flip benchmark produced only about:

    8.4 FPS

This does NOT necessarily mean the Pi CPU is overloaded.

The important application optimisation was to stop redrawing the entire
480x320 screen continuously.

The V0.4 optimisation uses: - fast event/input polling - redraw only
when needed - approximately 125 ms redraw interval for animated pages -
MOUSEBUTTONDOWN for X11 touch input - radio/audio updates independently
of expensive full-screen drawing

Do not casually return the program to an unconditional:

    pygame.display.flip()

on every 30/60 Hz loop iteration.

That previously made touch input feel severely delayed because each SPI
screen update could block for roughly 120 ms.

19. CURRENT RADIO-PAGE QUIRK

The DATA -> RADIO page can still feel somewhat slower to tap/select than
the other pages while music is playing.

Other pages respond normally while the same music continues playing.

This suggests the remaining lag is specific to radio-page
drawing/workload rather than the touchscreen, operating system or audio
output.

Do NOT recalibrate the touchscreen to fix a problem that happens only on
the Radio page.

24. BASIC TROUBLESHOOTING ORDER

If something goes wrong, avoid changing five things at once.

A useful order is:

A. PI WILL NOT STAY STABLE / RANDOM REBOOT

1.  Check power.

2.  Run:

    vcgencmd get_throttled journalctl -b -p err

Undervoltage has already been observed on this build.

B. SSH DOES NOT CONNECT

Try:

    ssh oliver@raspberrypi.local

Then from Windows:

    arp -a

The old 192.168.0.186 address may simply have changed.

C. PIP-BOY DOES NOT OPEN FROM DESKTOP

Try manually:

    cd ~/pipboy
    DISPLAY=:0 SDL_VIDEODRIVER=x11 python3 pipboy_v04.py

The terminal output will normally reveal the actual Python/Pygame error.

D. DISPLAY WORKS BUT TOUCH IS WRONG

Check:

    DISPLAY=:0 xinput list
    DISPLAY=:0 xinput list-props <TOUCH-ID>
    DISPLAY=:0 xinput test <TOUCH-ID>

Compare against the known-good calibration in this manual.

Do NOT immediately reinstall the LCD driver.

E. AUDIO DOES NOT COME FROM AUX

Check:

    aplay -l
    wpctl status

Then select the current bcm2835 Headphones sink.

F. AUDIO CRACKLES ONLY IN PIP-BOY

Check that pygame.mixer.pre_init(… buffer=4096) still appears BEFORE
pygame.init().

G. BOOT SUDDENLY TAKES ~90 SECONDS

Check:

    systemd-analyze
    systemd-analyze blame
    systemctl --failed

Remember the previous LightDM / renderD128 issue and inspect the local
LightDM override before changing unrelated services.

25. THINGS NOT TO CHANGE RANDOMLY

The following parts were difficult to get working together and should be
treated as known-good configuration:

-   dtoverlay=piscreen,speed=18000000,drm,rotate=180
-   ADS7846 touchscreen driver
-   Calibration: 3936 227 70 3900
-   SwapAxes 1
-   TransformationMatrix: 0 -1 1 -1 0 1 0 0 1
-   local LightDM service override
-   disabled old fbcp startup
-   Pygame X11 launch
-   pygame.mixer.pre_init(… buffer=4096)
-   optimized/dirty redraw approach

When troubleshooting, diagnose the affected subsystem first instead of
reinstalling drivers or replacing working configuration.
