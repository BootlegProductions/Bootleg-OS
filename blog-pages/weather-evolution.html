From university weather app to Weather Station

An Advanced Front-end brief became the starting point for one of the most developed Bootleg OS applications.

In this post Then: a searched OpenWeatherMap dashboard. Now: forecasts, geolocation, map layers and weather stories.

The original idea

The university specification called for a searched weather dashboard using OpenWeatherMap. It needed to show conditions, temperature, humidity and wind speed, with the data rendered dynamically instead of being written into the page.

That work also introduced the less glamorous parts of an application: what happens when a location cannot be found, when a request fails, or when the interface needs to explain that it is still loading. I explored progressive-web-app features and an SVG clock driven by the visitor’s local time as well.

Rebuilding it for Bootleg OS

The current Weather Station takes the same basic idea much further. It can use geolocation, resolve location names, show hourly and seven-day forecasts and place weather layers on an interactive map. Current weather stories give the data more context than a single icon and number can provide.

The layout has changed alongside the features. A forecast needs to be scannable at a glance, but it should also let somebody dig into the next few hours or a different location without losing their place.

What the old work taught me

Revisiting the coursework made it clear that the first version was a useful blueprint, even though its interface and code needed reworking. The important part was the idea of making external data understandable and pleasant to use.

The next steps are visual as much as technical: refining weather symbols, improving the small-screen layout and carrying some of the clock work into the wider application suite. The project can keep changing with the weather.
