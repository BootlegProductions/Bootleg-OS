Building Bootleg OS in public

A working portfolio is never really finished. Here is what has changed and what I am building next.

In this post Current focus: clearer project stories, working applications and a gallery that can grow with new work.

From archive to working site

Bootleg OS began as a way to bring older university work, graphics and experiments back together. As I restored the material, I wanted visitors to do more than scroll through screenshots. The site now has its own project pages, gallery folders, blog and small applications that can actually be used.

The home page is deliberately somewhere between a portfolio and a desktop. That structure lets very different pieces of work sit together without pretending they were all made for the same purpose.

What has changed

The project pages now make room for the story behind each piece of work as well as its images. The Pi-Boy, for example, has a growing archive of drawings and build media; the case study can show the idea, the physical shell and the work still to come.

I have also been refining the visual language across the site: warmer sunset colours, clearer reading layouts, a proper showcase reel and a blog that feels like part of the same place. These changes make the older material easier to explore while leaving room for new projects.

The useful mess in the middle

Not every part of this process is a polished reveal. Some assets survive in several versions, some ideas need rebuilding from an old folder, and a design that looks good on one screen can feel cramped on another. Working through those problems is part of the project.

Keeping the site alive gives me somewhere to test an idea, see how it behaves and revise it. That is more honest to the way I actually make things than presenting every experiment as if it arrived fully formed.

Next boot

I want to keep adding context to the project archives, improving the applications and writing about the choices behind the work. Bootleg OS should continue to grow as the work does.
